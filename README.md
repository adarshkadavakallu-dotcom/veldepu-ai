17. FRONTEND FORM BEHAVIOUR



Because this is FRONTEND ONLY:



Do NOT pretend the form is connected to a backend.



Instead implement a clean frontend submission state.



When submitted:



1. Validate fields.

2. Show loading state.

3. Prevent multiple clicks.

4. Show a professional success state.

5. Reset the form after success if appropriate.



Use a clearly labeled frontend/demo submission behavior.



Do not claim:



"Your data has been saved to our database"



because there is no backend yet.



Use wording such as:



"Thanks! Your project request is ready to be submitted."



If the existing environment provides a built-in form mechanism, use it only if it does not require creating a backend.
